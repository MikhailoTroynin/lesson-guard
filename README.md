# Lesson Guard

Android-додаток для батьків. Він стежить за завданнями дитини в **Google Класі** та оцінками в **«Єдиній школі»** і надсилає сповіщення, коли:

- 📘 вчитель додав **нове завдання** (наприклад, у понеділок);
- ⛔ за урок/завдання з’явилася **погана оцінка** (за замовчуванням нижче 7 за 12-бальною шкалою, поріг налаштовується). Оцінка автоматично прив’язується до завдання з цього предмета, тож видно, що «5 у середу» — це за «Задачі № 112–118» з понеділка;
- ⚠️ дитина **здала порожню роботу**: позначила «Здано», але нічого не прикріпила, або прикріплений Google-документ/презентація/таблиця порожні.

Перевірка запускається у фоні кілька разів на день, а також вручну (кнопка «Перевірити зараз» або потягнути екран вниз).

## Веб-версія

**https://mikhailotroynin.github.io/lesson-guard/**

Сайт відкривається в демо-режимі на вигаданих даних: натискайте «Наступний день ▶», щоб пройти тиждень (нове завдання → порожня здача → оцінка 5).

На сайті можна й **по-справжньому увійти в Google Клас дитини**: **Налаштування → Google Клас → Увійти через Google**. Після входу демо-режим вимикається сам, і додаток показує справжні завдання, здачі й порожні роботи. Потрібен OAuth client ID типу *Web* (див. «Підключення Google Класу», крок 5).

Особливості браузерної версії:

- Токен Google живе 1 годину і зберігається лише в цьому браузері. Коли він спливе, натисніть «Перевірити зараз»: відкриється коротке вікно Google і сесія оновиться (дозвольте спливаючі вікна для сайту).
- Поки вкладка відкрита, перевірка запускається кожні 30 хв, а нові алерти показуються як сповіщення браузера. Коли вкладку закрито, нічого не перевіряється — для фонових сповіщень потрібен Android-додаток.
- «Єдина школа» з браузера недоступна: її сайт не приймає запити з інших доменів (CORS), а пароль батьків не варто тримати в браузері.

На комп’ютері демо показується в макеті смартфона (як у дизайні), на телефоні — на весь екран.

> Демо збирається через `npx expo export --platform web` і публікується workflow-ом `.github/workflows/pages.yml` (GitHub Actions → Pages, без гілки `gh-pages`). Один раз увімкніть: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Після цього кожне оновлення `main` перезбирає сайт. Адреса: https://mikhailotroynin.github.io/lesson-guard/

### Автоматичне злиття в `main`

Workflow **Auto-merge to main** (`.github/workflows/auto-merge.yml`) спрацьовує на push у будь-яку гілку, крім `main`, `gh-pages`, `robot-data` і `setup/**`: проганяє lint, typecheck, тести й веб-збірку, а потім вливає гілку в `main` (fast-forward або merge-коміт) і запускає деплой GitHub Pages та збірку APK. Якщо на `main` увімкнено захист гілки, дозвольте `github-actions[bot]` пушити в неї, інакше крок злиття впаде.

## Встановлення на Android

1. Відкрийте вкладку **Actions → Android APK**, виберіть останній успішний запуск і завантажте артефакт `lesson-guard-apk`. Для версій із тегом `v*` APK також прикріплюється до **Releases**.
2. Встановіть APK на телефон (дозвольте встановлення з невідомих джерел).
3. Дозвольте сповіщення.
4. Спершу додаток відкривається в демо-режимі. Щоб бачити реальні дані, підключіть акаунти (нижче) і вимкніть «Демо-режим» у налаштуваннях.

## Найпростіше підключення: хмарний робот

Нічого не треба налаштовувати в Google Cloud. Робот — це браузер (Playwright + Chromium), який раз на годину запускається в GitHub Actions, сам заходить у «Єдину школу» і Google Клас акаунтом дитини та збирає оцінки, завдання і здані роботи. Результат він шифрує паролем і кладе в гілку `robot-data`. Додаток на телефоні завантажує цей файл і розшифровує тим самим паролем. Репозиторій публічний, тому без пароля дані прочитати неможливо.

### 1. Секрети в GitHub

**Settings → Secrets and variables → Actions → New repository secret**:

| Секрет | Що вписати |
|---|---|
| `ROBOT_PASSPHRASE` | довгий випадковий пароль, наприклад 4–5 випадкових слів (від 12 символів). Зашифровані дані лежать у публічному репозиторії, тож слабкий пароль можна підібрати, а разом із ним і сесію Google дитини |
| `ESCHOOL_LOGIN` | логін **дитини** на [diary.eschool-ua.com](https://diary.eschool-ua.com/) (номер телефону `380…`) |
| `ESCHOOL_PASSWORD` | пароль дитини в «Єдиній школі» |
| `GOOGLE_SESSION` | рядок з кроку 2 |

### 2. Один раз увійти в Google (на комп’ютері)

Google не дозволяє автоматизованому браузеру входити паролем (показує «Можливо, цей веб-переглядач небезпечний»). Тому один раз входите ви самі, у звичайному Chrome, а робот далі користується цією сесією й сам її продовжує.

Потрібні Node.js 22 і Google Chrome.

```bash
git clone https://github.com/MikhailoTroynin/lesson-guard.git
```

```bash
cd lesson-guard && npm install
```

```bash
npm run robot:session
```

Скрипт спитає пароль робота (той самий, що в `ROBOT_PASSPHRASE`) і відкриє вікно Chrome. Увійдіть акаунтом дитини. Коли відкриється Google Клас, вікно закриється, а поруч з’явиться файл `google-session.txt`. Скопіюйте з нього весь рядок у секрет `GOOGLE_SESSION`, а файл видаліть.

Якщо Google колись «розлогінить» робота (наприклад, дитина змінила пароль), у вкладці **Actions** з’явиться червоний запуск з поясненням. Тоді повторіть цей крок.

### 3. Запустити робота

**Actions → Robot → Run workflow.** Далі він запускається сам щогодини з 7:00 до 22:00 за Києвом.

> Розклад GitHub виконує лише з **гілки за замовчуванням**. Переконайтеся, що це `main`: **Settings → General → Default branch**.
>
> Якщо в репозиторії 60 днів немає нових комітів, GitHub вимикає розклад і надсилає лист. Тоді в **Actions → Robot** натисніть **Enable workflow**.

### 4. Увімкнути в додатку

**Налаштування → Хмарний робот:** введіть пароль робота і натисніть «Зберегти», потім вимкніть «Демо-режим». Помилки робота (наприклад, «неправильний пароль Єдиної школи») показуються там само.

### Якщо щось не працює

Запустіть **Robot → Run workflow** з галочкою *debug*. До запуску прикріпиться архів скріншотів сторінок `robot-debug-encrypted`. Він зашифрований паролем робота, бо там дані дитини. Розшифрувати його можна так:

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -in robot-debug.tgz.enc -out robot-debug.tgz
```

Робот читає вебсторінки так само, як людина в браузері. Якщо Google або «Єдина школа» змінять вигляд сайту, робота доведеться підлаштувати за цими скріншотами.

## Підключення Google Класу

Це альтернатива хмарному роботу: телефон сам ходить у Classroom API. Додаток читає дані через Google-акаунт **дитини** (лише читання). Батьківський доступ (guardian) через API не показує зданих робіт, тому потрібен саме акаунт дитини.

Одноразове налаштування в [Google Cloud Console](https://console.cloud.google.com/):

1. Створіть проєкт.
2. **APIs & Services → Library:** увімкніть **Google Classroom API** і **Google Drive API**.
3. **OAuth consent screen:** тип *External*, режим *Testing*. У **Test users** додайте email дитини. У режимі тестування верифікація від Google не потрібна.
4. **Credentials → Create credentials → OAuth client ID → Android:**
   - Package name: `com.mikhailotroynin.lessonguard`
   - SHA-1: `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25` (стандартний debug-ключ, яким підписується APK з Actions). Якщо ви налаштували власний ключ (див. нижче), вкажіть його SHA-1.
5. **Для веб-версії** створіть також OAuth client ID типу **Web application**:
   - **Authorized JavaScript origins:** `https://mikhailotroynin.github.io` (для локальної розробки ще `http://localhost:8081`). Redirect URI не потрібні.
   - Додайте ID у репозиторій як змінну `GOOGLE_WEB_CLIENT_ID` (**Settings → Secrets and variables → Actions → Variables**) і перезапустіть **Deploy demo to GitHub Pages**. Без змінної ID можна вписати прямо на сайті в налаштуваннях Google Класу — він збережеться в браузері.
   - Client ID не є секретом: він і так видимий у коді сторінки. Змінна `GOOGLE_WEB_CLIENT_ID` використовується також Android-збіркою.

Потім у додатку: **Налаштування → Google Клас → Увійти через Google**.

Скоупи, які запитує додаток:

| Скоуп | Навіщо |
|---|---|
| `classroom.courses.readonly` | список курсів дитини |
| `classroom.coursework.me.readonly` | завдання та здані роботи дитини |
| `drive.readonly` | перевірити, чи прикріплені документи не порожні |

Шкільні акаунти Google Workspace for Education можуть блокувати сторонні додатки на рівні адміністратора школи. У такому разі вхід поверне помилку доступу, і доведеться просити адміністратора дозволити додаток.

## Підключення «Єдиної школи» напряму з телефону

**Налаштування → Акаунти дитини → Єдина школа:** введіть логін (номер телефону дитини `380…`) і пароль з [eschool-ua.com](https://eschool-ua.com/login) і натисніть «Увійти». Додаток одразу перевіряє вхід на сайті. Якщо логін або пароль неправильні, ви побачите помилку. Після успішного входу демо-режим вимикається сам, і оцінки підтягуються під час кожної перевірки.

- Логін і пароль зберігаються лише на телефоні, у зашифрованому сховищі Android. Токен сесії теж, тож заново додаток входить тільки коли сесія закінчиться.
- Потрібен логін **дитини**. Акаунт батьків не має профілю учня, і додаток про це скаже.
- Вхід на сайті — це Next.js server action. Його id змінюється з оновленнями сайту, тому додаток сам знаходить новий id у JS-файлах сторінки входу (`src/providers/eschool/client.ts`).
- У браузері (GitHub Pages) вхід не працює: сайт Єдиної школи не приймає вхід з інших доменів (CORS).

Коли підключено і Google, і Єдину школу, хмарний робот не потрібен. Якщо його налаштовано, він підставляється лише для джерела, яке напряму не підключене.

## Деплой: Telegram-сповіщення (Cloudflare Workers + D1)

Сповіщення батькам у Telegram надсилає Cloudflare Worker з каталогу `worker/`, а дані зберігаються в базі D1 `lesson-guard`. Розгортання йде лише з GitHub Actions (`.github/workflows/deploy.yml`), локально нічого деплоїти не треба.

```
worker/
  wrangler.toml          конфіг Worker: name = lesson-guard, D1 binding DB
  src/index.ts           GET /health, POST /telegram/webhook (поки без логіки)
  migrations/0001_init.sql  початкова схема D1
  .dev.vars.example      імена локальних секретів (без значень)
```

Що вже вміє Worker:

| Маршрут | Що робить |
|---|---|
| `GET /health` | `{"ok":true,"service":"lesson-guard"}` |
| `POST /telegram/webhook` | приймає запит лише з правильним заголовком `X-Telegram-Bot-Api-Secret-Token`, інакше 401. Оновлення поки не обробляє |

Таблиці D1: `children` (діти), `telegram_chats` (чати батьків), `chat_children` (хто отримує сповіщення про яку дитину), `assignments` (завдання), `grades` (оцінки), `notifications_log` (журнал надісланих сповіщень; `UNIQUE (chat_id, dedupe_key)` не дає надіслати те саме двічі).

### Що має бути в GitHub

**Settings → Secrets and variables → Actions.**

| Тип | Назва | Що це |
|---|---|---|
| secret | `CLOUDFLARE_API_TOKEN` | API-токен Cloudflare з правами Workers Scripts: Edit і D1: Edit |
| secret | `TELEGRAM_BOT_TOKEN` | токен бота від @BotFather |
| variable | `CLOUDFLARE_ACCOUNT_ID` | ID акаунта Cloudflare |
| variable | `CLOUDFLARE_D1_DATABASE_ID` | ID бази D1 `lesson-guard` |

Окремий секрет для вебхука не потрібен: Worker і скрипт реєстрації обчислюють його з токена бота як `hex(HMAC-SHA256(токен, "lesson-guard:telegram-webhook"))`. Якщо змінити токен у @BotFather і в GitHub, наступний деплой сам перереєструє вебхук з новим секретом.

ID бази в `worker/wrangler.toml` не зберігається: там стоїть плейсхолдер `__D1_DATABASE_ID__`. Перед кожним запуском wrangler workflow замінює його значенням змінної `CLOUDFLARE_D1_DATABASE_ID` (`sed`) і падає, якщо змінна порожня, не схожа на UUID або плейсхолдер лишився.

`TELEGRAM_BOT_TOKEN` потрапляє у Worker через параметр `secrets` у `cloudflare/wrangler-action`: значення передаються у `wrangler secret bulk` через stdin і в лог не виводяться.

### Як запускається деплой

- **Автоматично:** push у `main`, який змінює `worker/**` або `deploy.yml` (тобто після мерджу PR).
- **Вручну:** **Actions → Deploy Worker → Run workflow → action = `deploy`**.

Міграції D1 автоматично **не** застосовуються.

### Як застосувати міграції

**Actions → Deploy Worker → Run workflow → action = `migrate`.** Job показує список міграцій і застосовує ті, яких ще немає в базі (`wrangler d1 migrations apply lesson-guard --remote`). Повторний запуск безпечний: застосовані міграції пропускаються.

Нова міграція — це новий файл `worker/migrations/000N_опис.sql`. Уже застосовані файли не редагуйте.

### Піддомен workers.dev (один раз, вручну)

Worker публікується на `https://lesson-guard.<піддомен>.workers.dev`. Якщо піддомен ще не зареєстровано, перший деплой упаде з помилкою на кшталт *«You need to register a workers.dev subdomain before publishing to workers.dev»*. До цього моменту wrangler уже встигне створити порожній Worker і записати секрети — це нормально.

1. Відкрийте [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages**.
2. Праворуч у блоці **Account details** (або **Settings → Subdomain**) натисніть **Change / Set up** біля *Subdomain* і введіть назву, наприклад `lessonguard`. Назва буде видна в адресі Worker.
3. Дочекайтеся, поки піддомен стане активним (буває до кількох хвилин).
4. **Actions → Deploy Worker → Run workflow → action = `deploy`** (або **Re-run failed jobs** у запуску, що впав).
5. Перевірте: `https://lesson-guard.<піддомен>.workers.dev/health` має повернути `{"ok":true,...}`.

### Вебхук Telegram

Реєструється автоматично: після `wrangler deploy` job запускає `worker/scripts/set-webhook.mjs`, який
1. перевіряє `GET /health` задеплоєного Worker'а;
2. викликає `setWebhook` з адресою `…/telegram/webhook` і секретом, виведеним з токена;
3. перевіряє через `getWebhookInfo`, що Telegram запам'ятав саме цю адресу.

Токен передається скрипту лише через змінну середовища, секрет маскується в лозі. Повторний деплой безпечний: `setWebhook` ідемпотентний.

### Локальна перевірка (без доступу до Cloudflare)

```bash
cd worker && npm ci
```

```bash
npm run check   # tsc + wrangler deploy --dry-run (нічого не публікує)
```

Для `npm run dev` скопіюйте `worker/.dev.vars.example` у `worker/.dev.vars` і впишіть значення. Файл `.dev.vars` у git не потрапляє.

## Власний ключ підпису (необов’язково)

Без налаштувань APK підписується стандартним debug-ключем. Щоб підписувати власним ключем, згенеруйте keystore і додайте секрети репозиторію:

```bash
keytool -genkeypair -v -keystore release.keystore -alias lessonguard -keyalg RSA -keysize 2048 -validity 10000
```

```bash
base64 -w0 release.keystore
```

Секрети: `ANDROID_KEYSTORE_BASE64` (вивід останньої команди), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Не забудьте вказати SHA-1 нового ключа в Google Cloud (`keytool -list -v -keystore release.keystore`).

### Структура

```
src/app/            екрани (Expo Router): Огляд, Сповіщення, Налаштування
src/core/           правила без залежностей від платформи (покриті тестами)
  rules.ts          погана оцінка, порожня здача, нормалізація назв
  matcher.ts        прив’язка оцінки до завдання (предмет + дата)
  checker.ts        одна перевірка: дані + попередній стан → нові алерти
src/providers/      джерела даних: Google Клас, Єдина школа, демо-сценарій
src/services/       збирання даних і повна перевірка (для екрана й фону)
src/platform/       сховище, секрети, сповіщення, фонова задача, вхід Google
worker/             Cloudflare Worker + D1 для Telegram-сповіщень (див. «Деплой»)
robot/              хмарний робот (Playwright): Єдина школа, Google Клас, шифрування
  run.ts            один запуск у GitHub Actions → robot-data/snapshot.json
  session.ts        `npm run robot:session` — одноразовий вхід у Google
```

Стек: Expo SDK 58 (React Native), TypeScript, Expo Router, expo-notifications, expo-background-task, `@react-native-google-signin/google-signin`, Vitest.

### Як працює перевірка

- **Нові завдання.** Завдання, яких не було на попередній перевірці. Під час першого запуску додаток лише запам’ятовує наявні завдання, щоб не завалити батьків старими.
- **Погані оцінки.** Оцінки за останні 7 днів, нижчі за поріг. «н», «зар.» та інші нечислові записи ігноруються.
- **Прив’язка оцінки до завдання.** Курс Google Класу зіставляється з предметом за назвою; номер класу на кшталт «7-А» відкидається. Якщо назви різні, відповідність задається в налаштуваннях. Обирається найближче завдання цього предмета, видане не пізніше дня оцінки й не раніше ніж за 14 днів.
- **Порожня здача.** Робота у статусі «Здано»/«Перевірено», у якої немає відповіді й вкладень, або всі вкладені файли порожні. Посилання, відео, форми й документи з картинками (наприклад, фото зошита) вважаються змістом. Якщо файл не вдалося прочитати, тривога не здіймається.
- Кожен алерт надсилається лише один раз.

### Обмеження

- Android сам вирішує, коли запускати фонову задачу. Інтервал близько 4 годин, але система може відкладати запуск, особливо в режимі енергозбереження.
- Під час першого запуску робот не знає, коли було видано старі завдання, і вважає їх виданими в день запуску. Через це оцінки за них можуть не прив’язатися до завдань. Нові завдання робот бачить протягом години після публікації, тож для них дата правильна.
- Хмарний робот читає вебінтерфейс Google Класу. Він бачить лише завдання з розділу «Завдання» (призначені, пропущені, виконані) і перевіряє вміст до 15 останніх зданих робіт за запуск.
- У веб-версії напряму працює лише Google Клас (без «Єдиної школи») і лише поки вкладка відкрита. Через хмарного робота веб-версія бачить і оцінки.
